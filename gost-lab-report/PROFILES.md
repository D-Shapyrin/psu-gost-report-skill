# Профили типов работ

Профиль — дефолтная структура и ожидания по типу работы. Оформление тела задаётся профилем вуза (`templates/<profile>/reference.docx`; для профиля `my` это типографика ПГУ ИБСТ — см. `templates/my/RULES.md`), профиль типа работы отвечает за структуру разделов. Контентный вход пользователя (методичка, положение вуза) **приоритетнее профиля** — см. «Приоритет требований» в SKILL.md.

Подписные документы (задание, дневник практики, отзывы, рецензии) скилл не генерирует — пользователь вкладывает их сам, профиль лишь напоминает об их месте.

## Лабораторная работа

Титульник — по вузу пользователя из реестра `templates/<profile>/title_pages/registry.yaml` (для профиля `my` — `pgu_lab`). Содержание обычно не нужно (`add_toc` не ставить); нумерация разделов — по правилу профиля вуза (для `my` — включена).

Структура отчёта жёстко задана и одинакова для всех лабораторных — не «гибкая»:

| № | Раздел | Когда нужен |
|---|---|---|
| 1 | **Цель работы** | Почти всегда. Одно-два предложения |
| 2 | **Задание к лабораторной работе** | Если в методичке есть пронумерованный список заданий — подразделы 2.1, 2.2… по пунктам задания |
| 3 | **Результаты работы** | Обязательно. Подразделы 3.1, 3.2… — что получено по каждому пункту задания |
| 4 | **Вывод** | Обязательно. Перекличка с целью; формулировка «В результате выполнения работы был…» |

Отдельных разделов «Вариант», «Краткие теоретические сведения», «Ход работы», «Тестирование» в структуре нет. Вариант — одной строкой в начале цели (например, «Цель работы. Вариант 5. …»); теория, ход действий и скриншоты тестирования идут **внутри** соответствующих подразделов «Результатов работы». Собственный раздел допустим только по прямому требованию методички или пользователя — тогда он вклинивается в схему, и последующие номера (прежде всего «Вывод») сдвигаются. Обычно дополнительные разделы не нужны.

**Цель и вывод — в строке заголовка.** Эти разделы короткие (одно-два предложения), поэтому текст пишется в той же строке, что и заголовок, через двоеточие: `# Цель работы: Изучить…`, `# Вывод: В результате выполнения работы был…`. Сборка нумерует заголовок как обычно («1 Цель работы: …»), текст остаётся на той же строке и выглядит как обычный текст (заголовочный стиль не жирный и не крупнее тела). Разделы с подразделами («Задание», «Результаты работы») оформляются обычным образом — заголовок отдельно.

**ПГУ ИБСТ (профиль `my`).** Кафедральный шаблон отчёта (`templates/my/Шапырин лабораторная работа № .docx`) задаёт ровно эту нумерованную структуру:

```markdown
# Цель работы: Текст...

# Задание к лабораторной работе
## Текст задания 1
## Текст задания 2

# Результаты работы
## Был создан новый проект, при этом тип используемой микросхемы ПЛИС был установлен аналогично лабораторной работе №1...
## Были разработаны интерфейс и архитектура модуля кодирования в соответствии с полученным вариантом задания...

# Вывод: В результате выполнения работы был...
```

YAML для такой работы: `number_headings: "true"`, `sections_new_page` не ставить (отчёт компактный), перечисления — дефисом (`lists_style: pgu` по умолчанию профиля). Цель и задание — дословно из методички; в «Результатах работы» — что именно получено, со ссылками на рисунки/таблицы. Заголовки разделов и подразделов пишутся **без номеров** — номера («1», «2.1», «3.2») проставляет сборка.

**Соответствие «Результаты работы» ↔ пункты задания.** Нумерация подразделов 3.x **не обязана** пунктуально совпадать с пунктами 2.x: часть пунктов задания закрывается в одном подразделе (если результаты связаны), пункт может состоять из нескольких подразделов, а пункты «оформить отчёт», «сделать выводы» отдельного подраздела не требуют. Контент в 3.x — дословные формулировки того, что сделано (по образцу шаблона: «Был создан новый проект, при этом…», «Были разработаны интерфейс и архитектура модуля кодирования в соответствии с полученным вариантом задания…»). Правило: каждое подразделение «Результатов работы» соответствует ровно одному (или нескольким связанным) пункту задания, и каждый содержательный пункт задания закрыт хотя бы одним подразделом.

### Цель работы

Заголовок-строка `#` с текстом цели через двоеточие, в одну строку: `# Цель работы: Изучить…`. Текст — одно-два предложения (в персональных профилях метка может быть жирной, см. правило профиля вуза). Глаголы — в начальной форме или в прошедшем времени по образцу методички: «изучить…», «исследовать…», «разработать…».

Если задана в методичке — брать **дословно**. Если нет — формулировать кратко и конкретно. Вариант — строкой в начале цели («Цель работы. Вариант 5. …»), отдельным разделом «Вариант» не выносить.

### Задание к лабораторной работе

Раздел `#`, внутри — **только** подразделы `##` по одному на пункт задания (2.1, 2.2…). Вступительной прозы и общего списка не добавлять: каждый пункт — дословная формулировка из методички, без перефразирования и сокращения и без точки в конце заголовка. Когда пунктов задания нет (или методичка даёт задание абзацами) — раздел без подразделов, текст дословно.

### Результаты работы

Раздел `#`, внутри — подразделы `##` (3.1, 3.2…), по одному на логический результат:

- Заголовок подраздела — формулировка того, что сделано, в прошедшем времени («Был создан новый проект, при этом тип используемой микросхемы ПЛИС был установлен аналогично лабораторной работе №1…»). Порядок — по пунктам задания.
- В подразделе: что именно получено (скриншоты, таблицы, листинги, измерения) со ссылками на рисунки и таблицы; ход действий — сжато, одним-двумя абзацами на блок.
- Описание действия → ссылка на группу рисунков: «Выполнение представлено на рисунках N-M»; скриншоты группируются по смыслу, а не описываются по одному.
- Один пункт задания может занять несколько подразделов, а близкие пункты — попасть в один подраздел. Пункты оформительского характера («оформить отчёт») подраздела не получают.

### Вывод

Заголовок-строка `#` с текстом через двоеточие, в одну строку: `# Вывод: В результате выполнения работы был…`.

- Должен подтверждать достижение цели работы
- Упоминать конкретные результаты (что настроено, реализовано, проверено)
- Перекликаться с формулировкой цели по смыслу (не дословное копирование)
- Начинается формулировкой «В результате выполнения работы был…» (по шаблону); в профиле ПГУ заголовок — в единственном числе: `# Вывод:`, не «Выводы:»
- Нумеруемый раздел — при появлении дополнительных разделов номер сдвигается (например, «5 Вывод:»); в Markdown номер по-прежнему не пишется

## Курсовая работа / курсовой проект

Титульник вузовский — по вузу пользователя из реестра `templates/<profile>/title_pages/registry.yaml`. YAML: `add_toc: true`, `number_headings: true`, `sections_new_page: true`.

Структура (объёмы и количества — дефолтные ориентиры при отсутствии методички, не ограничения: разделов столько, сколько требуют тема и задание):
- **Введение** (ориентир 2–5 стр.): актуальность → объект и предмет исследования → цель → задачи (обычно 3–5, по ним строится основная часть и заключение)
- **Основная часть**: разделы с подразделами (типовая логика: теория → анализ/проектирование → реализация; ориентир 2–4 раздела)
- **Заключение** (ориентир 2–4 стр.): выводы по задачам из введения
- **Список использованных источников**: дефолт — в порядке цитирования по ГОСТ 7.0.100-2018; ориентир 5–15 позиций
- **Приложения** при необходимости: объёмный код, большие таблицы, диаграммы

**Большие работы (от ~30 стр.) не писать за один проход** — качество к концу деградирует (вода, повторы, потеря нити). Писать по разделам от согласованного аутлайна: один раздел за проход; в контексте каждого прохода держать аутлайн целиком + краткое резюме уже написанного (основные тезисы и выводы предыдущих разделов). После сборки всего документа — обязательное ревью по REVIEW.md.

Приложения: заголовок `# Приложение А` (сборка отцентрирует и закапсит), следующей строкой — название приложения; подписи рисунков/таблиц внутри — своя нумерация: «Рисунок А.1 — …», «Таблица А.1 — …»; ссылка из текста на каждое приложение обязательна.

**ПГУ ИБСТ (профиль `my`).** Структура строго по Положению и Распоряжению кафедры (`templates/my/RULES.md`): титульный лист → **задание** (подписной бланк кафедры, вкладывает пользователь, скилл его не генерирует) → **ОГЛАВЛЕНИЕ** (`toc_title: "ОГЛАВЛЕНИЕ"`) → введение → основной текст (главы, параграфы, пункты — нумерация «1», «1.1», «1.1.1») → заключение → **СПИСОК ИСПОЛЬЗУЕМЫХ ИСТОЧНИКОВ** (ГОСТ Р 7.0.5-2008) → приложения. Объём: КР — 20–25 страниц без приложений; КП — 30–40 страниц + 2–4 листа чертежей. Титульник — `pgu_course` + YAML `decimal_number`, `topic`, `discipline`, `specialization`, `student_name`, `group`, `teacher_name`, `year`. Источники по ГОСТ Р 7.0.5-2008.

## ВКР (бакалаврская / дипломная / магистерская)

Как курсовая, плюс: **реферат** — первым разделом Markdown, до всего остального (сборка сама поставит СОДЕРЖАНИЕ после него, по ГОСТ). Объём 50–120 стр., источников ≥25–50 в зависимости от уровня. Вузовские особенности (двуязычный реферат, автореферат) — только через контентный вход.

Шаблон реферата (счётчики подставит сборка — писать плейсхолдеры буквально):

```markdown
# Реферат

Пояснительная записка {{PAGES}} с., {{FIGURES}} рис., {{TABLES}} табл., {{SOURCES}} источн., {{APPENDICES}} прил.

КЛЮЧЕВЫЕ СЛОВА: ПЕРВОЕ, ВТОРОЕ, ТРЕТЬЕ (5–10 слов капсом, через запятую)

Объект исследования — … Цель работы — … Методы — … Полученные результаты — …
```

`{{PAGES}}` вычисляется через LibreOffice (как и авто-TOC); без LibreOffice остаётся плейсхолдер — предупредить пользователя.

## Отчёт по практике

Ядро как у курсовой; основная часть по программе практики: характеристика организации → поставленные задачи → выполненные работы → результаты. Индивидуальное задание/дневник — подписные, их место сразу после титула.

## Реферат

Титульник вузовский. Структура: содержание (при объёме >10 стр.) → введение (кратко: тема, цель) → 2–3 раздела → заключение → список источников. Объём 10–20 стр.

## Контрольная работа

Минимальная структура: задания как разделы («Задание 1», «Задание 2») с решениями → список источников при необходимости. Требования почти всегда «на усмотрение преподавателя» — контентный вход здесь главный, профиль лишь каркас.
